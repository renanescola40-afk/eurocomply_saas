# Legal Assurance — Production Enablement Gate

This checklist is intentionally **non-authorising**. Completing repository work does not grant authority to enable Legal Assurance in Production.

Current expected state:

```text
LEGAL_ASSURANCE_ENABLED=false
LAW_FIRM_PARTNER=PENDING
EXTERNAL_COUNSEL_VALIDATION=PENDING
PROFESSIONAL_RULES_VALIDATION=PENDING
LEGAL_COMMERCIAL_VALIDATION=PENDING
PUBLIC_COUNSEL_CLAIMS=PENDING
PRODUCTION_COUNSEL_ENABLEMENT=PENDING
```

## A. Repository acceptance

Before merge consideration:

- [ ] feature branch is based/reconciled against the intended release SHA;
- [ ] typecheck passes;
- [ ] lint passes;
- [ ] unit tests pass;
- [ ] security contract tests pass;
- [ ] migration/ephemeral Supabase tests pass;
- [ ] build passes;
- [ ] no Critical/High security regression introduced;
- [ ] no Enterprise V1 regression attributable to the feature;
- [ ] PR review is complete;
- [ ] owner explicitly authorises merge.

## B. Database acceptance

Before any Production migration push:

- [ ] migrations reviewed against current Production schema;
- [ ] migration order and dependency preconditions verified;
- [ ] RLS and FORCE RLS verified for every Legal Assurance table;
- [ ] authenticated mutation grants verified absent;
- [ ] service-role RPC privileges verified exact;
- [ ] customer cross-tenant denial tested;
- [ ] Counsel unassigned-matter denial tested;
- [ ] cross-law-firm denial tested;
- [ ] package immutability tested;
- [ ] decision immutability tested;
- [ ] state-transition concurrency tested;
- [ ] backup/recovery plan approved;
- [ ] owner explicitly authorises Production migration application.

## C. Server configuration

Required server configuration is deliberately fail-closed:

```text
LEGAL_ASSURANCE_ENABLED=false
LEGAL_ASSURANCE_METHODOLOGY_VERSION=<approved version>
LEGAL_ASSURANCE_REGULATORY_RULES_VERSION=<approved version>
VERCEL_GIT_COMMIT_SHA=<release SHA supplied by runtime>
```

Before enabling:

- [ ] methodology version approved for the release;
- [ ] regulatory-rules version approved for the release;
- [ ] exact Production release SHA known;
- [ ] environment values configured server-side only;
- [ ] no service-role or secret exposed to client bundles;
- [ ] feature remains OFF through migration/rehearsal.

- [ ] named Counsel professional identity verified;
- [ ] conflict process approved;

```text
LAW_FIRM_PARTNER=PENDING
EXTERNAL_COUNSEL_VALIDATION=PENDING
PROFESSIONAL_RULES_VALIDATION=PENDING
```

## E. Privacy/confidentiality acceptance

- [ ] controller/processor allocation approved;
- [ ] DPA/data-sharing terms approved;
- [ ] subprocessor implications reviewed;
- [ ] retention/deletion/legal-hold rules approved;
- [ ] confidentiality/professional secrecy requirements approved;
- [ ] privilege wording approved;

## F. Commercial acceptance

Launch default should remain:

```text

```

Before any other model:

- [ ] legal/professional rules permit structure;
- [ ] fee/referral rules reviewed;
- [ ] customer contracting updated;
- [ ] law-firm contracting updated;
- [ ] invoicing responsibility explicit;
- [ ] no unapproved percentage fee sharing;
- [ ] no unapproved Stripe Connect/payment split.

## G. Synthetic E2E acceptance

Complete at least one fully synthetic lifecycle:

```text
Customer requests review
→ verified synthetic Counsel assignment
→ conflict accepted
→ engagement accepted
→ Package V1 frozen
→ Counsel starts review
→ remediation required
→ customer remediates
→ customer resubmits
→ Package V2 frozen
→ Counsel starts re-review
→ Counsel accepts/accepts with conditions
→ signed-artifact reference exercised in private test storage
→ customer reads final state
→ unrelated tenant denied
→ unrelated Counsel denied
→ another firm denied
```

No synthetic fixture may resemble a real law-firm approval.

## H. Runtime/observability acceptance

- [ ] error codes observable without confidential payloads;
- [ ] package generation failure fails closed;
- [ ] audit persistence failure does not report professional-decision success;
- [ ] rate-limit provider failure fails appropriately;
- [ ] disabled-feature direct API access denied;
- [ ] audit chain contains expected safe events;
- [ ] expired decisions stop presenting current assurance;
- [ ] revoked grants remove Counsel matter access.

## I. Public/product acceptance

Before any public availability or marketing claim:

- [ ] public terminology approved by qualified Counsel;
- [ ] disclaimers approved;
- [ ] no global `COMPLIANT` state introduced;
- [ ] operational readiness remains distinct from external legal review;
- [ ] law-firm name/logo permission recorded;
- [ ] Trust Center Legal Assurance copy approved;
- [ ] customer plan/add-on commercial terms approved.

Until then:

```text
PUBLIC_COUNSEL_CLAIMS=PENDING
```

## J. Enablement sequence

Only after A–I are satisfied and owner approval exists:

1. identify exact approved Production release SHA;
2. apply reviewed forward-only migrations under explicit authority;
3. verify RLS/RPC postconditions in Production without exposing customer data;
4. configure approved methodology/rules version values;
5. create/activate only genuinely verified partner/Counsel records under authorised administration;
6. execute bounded synthetic/approved acceptance checks;
7. keep public claims disabled;
8. owner explicitly authorises feature enablement;
9. set `LEGAL_ASSURANCE_ENABLED=true` server-side;
10. verify customer/Counsel access and observability;
11. separately authorise any public launch/marketing change.

## K. Rollback / disablement

Primary emergency control:

```text
LEGAL_ASSURANCE_ENABLED=false
```

Disabling must immediately block customer/Counsel feature APIs without deleting historical records.

For a Counsel-specific incident:

- deactivate/revoke the affected matter grant;
- if necessary suspend the Counsel profile or firm;
- preserve historical packages/decisions/audit evidence;
- do not mutate issued professional decisions;
- investigate using safe operational metadata.

Database migrations are forward-only. Do not destructively roll back historical assurance evidence merely to disable the feature.

## Terminal authority rule

Repository completion may eventually support:

```text
LEGAL_ASSURANCE_IMPLEMENTATION=PASS
```

It may **not** by itself convert any external gate to PASS or authorise Production enablement.
