# Vercel Deployment Recovery Runbook

Purpose: recover Day 1 deployment evidence without pretending that a historical preview URL proves the current release candidate.

## Current status

The release remains **No-Go** until a successful Vercel deployment URL and build/deploy log exist for the exact commit under assessment.

A previous or historical preview URL can be used as rollback context only. It must not be used as current release proof unless the commit SHA matches the assessed commit and runtime smoke checks pass.

## Recovery sequence

1. Confirm the assessed GitHub commit SHA.
2. Re-run the Vercel deployment after the deployment quota/rate limit resets, or move the project to a Vercel capacity tier that can run the deployment.
3. Capture the Vercel deployment URL and build/deploy log URL.
4. Confirm the Vercel commit SHA matches the assessed GitHub commit SHA.
5. Run smoke checks against the current deployment URL:

```bash
export RELEASE_BASE_URL="https://<current-vercel-deployment-url>"
curl -fsS "$RELEASE_BASE_URL/api/health"
curl -fsS "$RELEASE_BASE_URL/api/ready"
```

`/api/ready` may require the correct protected runtime context. If credentials are required, store them only in the provider or secret manager. Do not commit secret values or authenticated response payloads.

6. Run final validation from a release runner:

```bash
RELEASE_TARGET=enterprise node scripts/release/run-final-validation.mjs
```

7. Attach the generated artifact bundle:

- `release-validation/summary.json`
- `release-validation/summary.md`
- `release-validation/logs/*.log`

8. Update `docs/RELEASE_APPROVAL_RECORD.md` only with observed evidence. Keep **No-Go** if any P0 remains open.

## Evidence required to close the deployment P0

| Evidence | Required value |
| --- | --- |
| Assessed commit SHA | Exact GitHub commit being promoted |
| Vercel deployment URL | Current deployment URL for the assessed commit |
| Vercel build/deploy log URL | Current build/deploy log for the assessed commit |
| Commit alignment | Vercel commit SHA equals assessed GitHub SHA |
| Health check | `/api/health` passes for the current deployment URL |
| Readiness check | `/api/ready` passes or fails with documented, expected P0 blocker |
| Final validation bundle | Generated by `scripts/release/run-final-validation.mjs` |

## Explicit non-evidence

These items are useful context but do not close the deployment P0 by themselves:

- Historical Vercel preview URLs from older PRs or commits.
- Vercel bot comments without a current deployment URL.
- A local build that is not tied to the deployed commit.
- A manually edited release approval document without command logs.
- Screenshots without commit, timestamp, environment, and redaction review.

## Rollback relationship

Rollback remains a separate P0 closure item. A rollback target can be recorded as a candidate while No-Go remains selected, but it is not verified until the previous known-good URL/SHA is smoke-tested and the rollback trigger criteria are accepted by the rollback owner.
