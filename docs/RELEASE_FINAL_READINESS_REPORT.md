## Executive summary

**No-Go.**

This update moves the release gate from public-production style validation to a stricter enterprise production gate. It adds an enterprise runtime evidence writer, a dedicated GitHub Actions workflow, observability smoke as a required final command, rollback dry-run evidence, branch-protection validation, and final `enterprise-runtime-evidence.json` / `release-go-no-go.json` outputs.

## Rollback plan

Rollback requires:

- `RELEASE_ROLLBACK_TARGET` or `LAST_KNOWN_GOOD_DEPLOYMENT_URL`.
- `RELEASE_ROLLBACK_TARGET_SHA` or `LAST_KNOWN_GOOD_COMMIT_SHA` / equivalent known-good SHA.
- `RELEASE_ROLLBACK_TARGET_VALIDATED=true` only after manual functional validation.
- Passing `npm run release:rollback:dry-run`.
- Non-destructive Supabase migration decision: prefer forward-fix unless a reversible migration is proven safe.
- Stripe webhook replay/idempotency verified before replay.
- Feature flags/env rollback tracked and revalidated.

Support readiness is **not approved for Enterprise Go** until final release support evidence passes. Minimum readiness requires:

- owner and escalation path;

Customer communication must avoid legal overclaims and must not mention internal stack traces, exploit detail, tokens, customer PII or secrets. Approved language should use “readiness”, “evidence preparation”, “governance workflows” and “compliance operations support”, not “guaranteed compliance” or “replaces legal counsel”.
