# Phase 2 Execution Plan

Phase 2 turns the repository-side gates into real CI, deployment, staging, and production validation.

## Day 1: local technical baseline

Required closeout command:

```bash
npm run phase2:day1:closeout
```

This command runs:

```bash
npm run phase2:day1
npm run phase2:day1:evidence
```

The Day 1 capture helper runs:

```bash
npm run supply-chain:lockfile
npm ci
npm run typecheck
npm run test
npm run build
```

Day 1 is complete only after `package-lock.json` is generated by npm and all Day 1 logs pass with `## exitCode: 0`.

Day 2 must not start until Day 1 evidence is committed and reviewed.

## Day 2: CI validation

Required CI sequence:

```bash
npm ci
npm run lint
npm run typecheck
npm run test
npm run build
npm run security:ci
```

Required outputs:

- install log
- lint log
- typecheck log
- test log
- build log
- security log
- uploaded artifacts for logs and test/build outputs

## Day 3: Vercel preview and production validation

Required checks:

- preview deploy completes
- production deploy completes
- health endpoint responds
- smoke test covers the deployed URL
- deployment logs are retained

## Day 4: Supabase staging and production validation

Required checks:

- staging project configured
- production project configured
- migrations applied intentionally
- RLS validation passes
- storage/security policies reviewed
- no service-role key is exposed to client code

## Later phases

After Phase 2, continue with:

- Stripe billing validation
- Sentry observability validation
- security hardening
- legal and trust evidence
- enterprise readiness

## Completion rule

Phase 2 is complete only when Day 1 through Day 4 have real logs or provider evidence attached to the release record.
