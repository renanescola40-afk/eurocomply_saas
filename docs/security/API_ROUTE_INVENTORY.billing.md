# Billing, Public Trust and Enterprise Modular API Route Inventory

This module extends `API_ROUTE_INVENTORY.md` for billing lifecycle, public trust surfaces and independently delivered Enterprise endpoints. Every entry is validated by the same fail-closed BOLA/IDOR scanner.

| Route | Class | Notes |
| --- | --- | --- |
| `src/app/api/billing/catalog/route.ts` | public safe | Public pricing and add-on metadata only; Stripe/provider identifiers and tenant data are excluded, responses are no-store, and distributed per-IP rate limiting is enforced. |
| `src/app/api/billing/checkout/activation/route.ts` | tenant-scoped | Read-only post-checkout activation status; requires an authenticated user, derives the current organization server-side from membership, reads only that organization's persisted subscription row, requires `active`/`trialing` plus exact Stripe customer/subscription IDs and a processed `livemode=true` Stripe subscription event correlated to the same tenant/customer/subscription before returning `activated`, applies fail-closed distributed rate limiting, returns no-store responses and exposes no browser-return/session authority. |
| `src/app/api/trust/procurement-pack/route.ts` | public safe | Public evidence-bound procurement metadata only; excludes tenant data, customer evidence, secrets and internal identifiers, emits conservative non-claims, uses same-origin trust-document links and bounded shared-cache headers. |
| `src/app/api/trust/security-questionnaire/route.ts` | public safe | Public evidence-bound security questionnaire metadata only; excludes tenant data, customer identifiers, private evidence, secrets and internal environment values, emits conservative non-claims and same-origin public evidence links. |
| `src/app/api/ops/legal-rules-validation/route.ts` | health/internal | Protected read-only deterministic legal-rules proof; applies fail-closed pre-authentication rate limiting, requires `INTERNAL_CRON_SECRET` or `CRON_SECRET`, exposes no tenant data, binds output to release metadata, fails closed with 503, sanitizes request identifiers and returns no-store, anti-frame, no-referrer, nosniff and no-index headers. |
| `src/app/api/billing/subscription/route.ts` | high-risk | Subscription lifecycle mutation requires authenticated server-derived organization context, `manage_billing`, trusted mutation, bounded Zod input, fail-closed billing rate limiting, step-up authentication, server-owned Stripe identifiers, audit persistence and no-store responses. |
| `src/app/api/team/break-glass/route.ts` | admin-only | Tenant emergency-access request creation and listing; requires authenticated organization context, `manage_team`, trusted mutation for POST, bounded JSON, distributed fail-closed rate limiting, step-up authentication, server-derived tenant scope, service-role persistence and no-store responses. |
| `src/app/api/team/break-glass/[requestId]/decision/route.ts` | high-risk | Emergency-access approval or rejection; requires UUID validation, authenticated organization context, `manage_team`, trusted mutation, distributed fail-closed rate limiting, step-up authentication, requester/approver separation, tenant-scoped persistence and no-store responses. |
| `src/app/api/team/break-glass/[requestId]/revoke/route.ts` | high-risk | Immediate emergency-access revocation; requires UUID validation, authenticated organization context, `manage_team`, trusted mutation, distributed fail-closed rate limiting, step-up authentication, tenant-scoped transition, post-incident-review scheduling and no-store responses. |
| `src/app/api/internal/enterprise-break-glass/expire/route.ts` | health/internal | Internal emergency-access expiry worker; requires fail-closed internal authentication rate limiting, cron authorization, bounded batch size, concurrency-safe processing, sanitized errors and no-store responses. |
| `src/app/api/ai-governance/article-50/route.ts` | high-risk | Authenticated Article 50 workspace read and mutation route; derives organization scope server-side, enforces `read_ai_governance` or `manage_ai_governance`, trusted origin for mutations, bounded Zod input, distributed fail-closed rate limiting, tenant-scoped AI-system and assessment lookups, audit persistence with compensating rollback, sanitized errors and no-store responses. |
| `src/app/api/ai-governance/fria/assignees/route.ts` | tenant-scoped | Read-only FRIA assignment directory; requires authenticated server-derived organization context and `manage_ai_governance`, validates the requested assessment inside the same tenant, enumerates only eligible tenant members, resolves only tenant-proven user identities, applies distributed rate limiting, returns minimized canonical assignment identity and no-store responses, and never accepts browser-supplied organization scope. |
| `src/app/api/gap-analysis/route.ts` | tenant-scoped | Authenticated Gap Analysis read and mutation boundary; derives organization scope server-side, enforces `read_ai_governance` or `manage_ai_governance`, applies trusted-origin protection for mutations, bounded Zod input, distributed fail-closed rate limiting, organization/user-scoped persistence, compensating rollback and audit evidence, sanitized errors and no-store responses. |
| `src/app/api/legal-assurance/route.ts` | high-risk | Customer Legal Assurance request/list boundary; default-OFF feature gate, authenticated server-derived organization scope, Enterprise `read_ai_governance`/`manage_ai_governance` RBAC, trusted origin for mutation, bounded Zod input, distributed fail-closed rate limiting, tenant-scoped AI-system validation, audit persistence with compensating rollback, sanitized errors and no-store responses. |
| `src/app/api/legal-assurance/[reviewId]/route.ts` | high-risk | Customer matter lifecycle boundary for package preparation, information response, remediation and resubmission; requires authenticated server-derived organization scope, Enterprise governance RBAC, tenant-scoped review lookup, optimistic state checks, trusted origin, bounded discriminated Zod input, distributed fail-closed rate limiting, immutable package/audit controls and no-store responses. |
| `src/app/api/legal-assurance/artifacts/[artifactId]/download/route.ts` | high-risk | Short-lived signed artifact download boundary; requires authentication, resolves either Enterprise customer authority or active verified assignment-scoped Counsel authority server-side, never trusts tenant/matter scope from the browser, applies distributed fail-closed rate limiting, audits request and issuance, signs a private bucket object for 60 seconds only and returns no-store responses. |
| `src/app/api/counsel/legal-reviews/route.ts` | high-risk | Matter-scoped Counsel inbox and conflict/engagement gate; requires authenticated user mapped to an active verified Counsel profile, assignment-bound matter lookup, trusted origin for mutation, bounded Zod input, distributed fail-closed rate limiting, atomic state gates, audit persistence and no-store responses; customer RBAC is intentionally not reused for external Counsel authority. |

| `src/app/api/counsel/legal-reviews/[reviewId]/artifacts/route.ts` | high-risk | Signed Counsel PDF upload boundary; default-OFF, trusted-origin protected, authenticated active verified Counsel plus explicit assigned matter, IN_REVIEW state only, bounded multipart size, PDF signature validation, malware-scan policy, distributed fail-closed rate limiting, private service-role storage, opaque artifact reference, compensating cleanup and audit persistence. |
| `src/app/api/internal/platform-proof/email/route.ts` | health/internal | Protected synthetic transactional-email proof; dedicated bearer token, fail-closed authentication rate limiting, exact deployed release-SHA binding, fixed provider test recipient, no arbitrary recipient input and no-store responses. |
