# Conformity Readiness Acceptance Checklist

A conformity workstream may be promoted only when all applicable items are evidenced against the exact integrated SHA.

## Applicability and route

- [ ] Provider/operator role is recorded and reviewed.
- [ ] High-risk applicability is supported by the canonical classification decision.
- [ ] Conformity route is selected with rationale.
- [ ] Interaction with product-safety legislation is reviewed.
- [ ] Notified-body involvement is determined by an accountable reviewer.
- [ ] Uncertain applicability or route has completed legal review.

## Prerequisite controls

- [ ] QMS version is approved and current.
- [ ] Risk-management evidence is complete.
- [ ] Data-governance evidence is complete.
- [ ] Annex IV technical documentation is complete and versioned.
- [ ] Record-keeping controls are evidenced.
- [ ] Transparency and instructions for use are complete.
- [ ] Human-oversight controls are evidenced.
- [ ] Accuracy, robustness and cybersecurity controls are evidenced.
- [ ] Post-market monitoring plan is approved.
- [ ] Incident process is approved.
- [ ] Standards and common-specification review is recorded.

## External assessment and certificates

- [ ] Required notified-body evidence is complete.
- [ ] Certificate authenticity and validity are independently checked.
- [ ] Certificate scope matches the AI system and version.
- [ ] No relied-upon certificate is expired.
- [ ] Severe nonconformities are closed and independently verified.

## Declaration and CE marking

- [ ] Declaration contains the required provider and system identifiers.
- [ ] Applicable legislation and standards references are included.
- [ ] Notified-body reference is included where applicable.
- [ ] Declaration is approved and signed by an authorised person.
- [ ] Signed declaration has a retained SHA-256 integrity digest.
- [ ] CE-marking applicability is reviewed.
- [ ] CE artwork, placement and release controls are approved.
- [ ] The workflow does not present readiness as authorization.

## Registration and release

- [ ] Registration applicability and database scope are reviewed.
- [ ] Required registration dataset is complete.
- [ ] Submitted dataset has a retained integrity digest.
- [ ] Submission actor and timestamp are recorded.
- [ ] Registration identifier and registered timestamp are retained.
- [ ] Substantial-modification assessment is complete.
- [ ] Owner, reviewer and approver are distinct where required.
- [ ] Final market-release decision is append-only.

## Runtime and evidence gates

- [ ] Migration passes in an isolated database.
- [ ] Positive and negative cross-tenant RLS tests pass.
- [ ] Actor membership triggers pass with two organizations.
- [ ] Exact-head lint, typecheck, tests and build pass.
- [ ] Human/legal methodology review is accepted.
- [ ] External interoperability evidence is retained where applicable.
- [ ] Canonical scorecard promotion records limitations.

Passing this checklist demonstrates evidence-backed readiness. It is not a certificate, official assessment, CE authorization, registration guarantee or legal opinion.
