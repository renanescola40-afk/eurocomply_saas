# MONDAY 14 SEP — FOUNDER POST

Theme: inventory != vendor list

## Publish copy — English

Most AI inventories start with a sensible question:

**Which AI tools are we using?**

That question is necessary — but it is not enough for governance.

A vendor name does not tell you:

- which business use case is active;
- who is accountable for it;
- which deployment/customer context matters;
- what provider/model dependencies exist;
- what governance rationale was recorded;
- what evidence supports the decision;
- what change should trigger another review.

A useful operating inventory connects:

`SYSTEM -> USE CASE -> OWNER -> PROVIDER / ROLE CONTEXT -> EVIDENCE -> REVIEW`

The goal is not to turn a spreadsheet into a legal classification engine.

The goal is to make the next governance question answerable without reconstructing the organisation from email, Drive and memory.

Question: if one owner left tomorrow, would your AI inventory still explain why each material use case exists and what should happen next?

# WEDNESDAY 16 SEP — FOUNDER POST

Theme: spreadsheet breakpoint

## Publish copy — English

Spreadsheets are not the problem.

They are often the right place to start an AI inventory.

The breakpoint appears when the inventory needs to do more than list rows.

You have reached that point when:

- the same provider supports several systems/use cases;
- different teams own different parts of the record;
- evidence becomes stale at different times;
- customer/security reviews need reusable answers;
- a model/provider change should reopen several records;
- you need history instead of the latest cell value;
- no one is sure which version is authoritative.

That is the transition from **inventory as spreadsheet** to **inventory as governance workflow**.

Start simple.

But design the fields so the record can survive that transition.
