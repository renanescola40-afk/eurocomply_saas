## Mission

Use Spain's unusually strong official RIA/AESIA content base to build a commercial authority layer that translates regulatory guidance into operational AI-governance workflows.

Core positioning:

> **Gobernanza operativa de IA para empresas europeas.**

Commercial mechanism:

`SISTEMA -> CASO DE USO -> RESPONSABLE -> PROVEEDOR/ROL -> RIESGO -> EVIDENCIA -> ACCIONES -> REVISIÓN`

## Search-market observation

Spanish search results currently contain substantial official and institutional material from the national digital authorities and AESIA, while the researched commercial SERP is less saturated by Spain-native AI-governance platforms than Germany or France.

That makes Spain an early-authority opportunity.

RISCK COMPLY should not compete with AESIA as a legal source. It should become the practical bridge between official guidance and day-to-day governance operations.

## LinkedIn ES — Post 1

Hook:

**Un inventario de IA que solo enumera herramientas no es suficiente para operar la gobernanza.**

Copy:

ChatGPT — Marketing.
Copilot — Finanzas.
IA de selección — RR. HH.

Puede ser una buena lista inicial.

Pero cuando llega una revisión, las preguntas cambian:

→ ¿Cuál es el caso de uso concreto?
→ ¿Quién es responsable?
→ ¿Quién es el proveedor?
→ ¿Qué papel tiene nuestra organización?
→ ¿Qué revisión se realizó?
→ ¿Qué evidencia respalda la decisión?
→ ¿Qué acciones siguen abiertas?
→ ¿Cuándo debe revisarse de nuevo?

Ahí es donde una lista empieza a convertirse en un sistema de gobernanza.

RISCK COMPLY está diseñada para mantener ese contexto conectado por sistema y caso de uso.

No es una clasificación jurídica automática ni una garantía de cumplimiento.

CTA:

**¿Cómo mantiene hoy tu organización el inventario de IA: Excel, GRC o un flujo dedicado?**

## LinkedIn ES — Post 2

Hook:

**España ya tiene 16 guías prácticas para el Reglamento de IA. El reto empresarial empieza después: convertir la orientación en trabajo operativo.**

Copy:

Las guías oficiales cubren áreas como gestión de riesgos, vigilancia humana, datos, transparencia, ciberseguridad, registros, documentación técnica y gestión de incidentes.

Pero dentro de una empresa todavía quedan preguntas operativas:

¿Quién es el responsable?
¿Qué sistema está afectado?
¿Qué revisión falta?
¿Qué evidencia existe?
¿Qué decisión se tomó?
¿Qué cambia si cambia el proveedor o el caso de uso?

La gobernanza no termina cuando se lee una checklist.

Empieza cuando esas obligaciones y revisiones tienen propietarios, contexto, fechas y evidencias que pueden volver a revisarse.

RISCK COMPLY está construida alrededor de esa capa operativa.

Información general, no asesoramiento jurídico.
