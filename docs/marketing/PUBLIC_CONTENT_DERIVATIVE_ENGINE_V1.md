# ASSET A — AI GOVERNANCE EVIDENCE MODEL

Core thesis:

**A file is not useful governance evidence until a reviewer can understand what it proves, for which system/use case, who relied on it, when it was valid and what changed afterward.**

## Founder post angle

Hook:

`Most AI governance teams do not have an evidence shortage. They have an evidence-context problem.`

Teach:

`FACT -> DECISION -> OWNER -> IMPLEMENTATION -> EVIDENCE -> REVIEW -> HISTORY`

Question:

`Could another reviewer reconstruct one material AI decision without asking five teams for context?`

## Company post angle

Title:

**Six tests for useful AI governance evidence**

List:

- relevance;
- specificity;
- authority;
- freshness;
- traceability;
- reproducibility.

CTA:

`Use the Evidence Model to review one material AI use case.`

## Carousel — 6 slides

1. `Your evidence is not missing. It is disconnected.`
2. `A PDF in Drive is not a governance chain.`
3. `FACT -> DECISION -> OWNER -> IMPLEMENTATION -> EVIDENCE -> REVIEW -> HISTORY`
4. `Test relevance / authority / freshness / traceability.`
5. `Ask: what change makes this evidence stale?`
6. `Attach evidence to the system/use-case record.`

## Newsletter angle

`Why stale AI evidence is more dangerous than missing evidence`

## Sales excerpt

`If I picked one AI use case, could your team reconstruct the facts, rationale, implementation evidence and review history without rebuilding the answer across several systems?`

# ASSET B — AI PORTFOLIO GOVERNANCE MAP

Core thesis:

**Product-level governance can be strong while portfolio-level governance remains fragmented.**

## Founder post angle

Hook:

`The moment your company has several AI products, agents or customer deployments, governance stops being a list problem and becomes a relationship problem.`

Teach:

`PORTFOLIO -> SYSTEM -> USE CASE -> OWNER -> PROVIDER/ROLE CONTEXT -> EVIDENCE -> REVIEW`

Buyer question:

`If one shared provider changes tomorrow, can you identify every affected use case and owner?`

## Company post angle

Title:

**10 questions an AI portfolio view should answer**

Priority questions:

- systems without owner;
- stale evidence;
- shared dependencies;
- review due/overdue;
- unresolved governance context;
- customer assurance requirements.

## Carousel — 7 slides

1. `One vendor row is not an AI portfolio.`
2. `One provider can support many systems.`
3. `One system can support several use cases.`
4. `Each use case can have a different owner/context.`
5. `Shared dependencies create change-propagation risk.`
6. `A provider change should reopen affected reviews.`
7. `Portfolio governance makes those relationships visible.`

## Newsletter angle

`The AI governance question your spreadsheet cannot answer after a provider change`

## Sales excerpt

`If a shared model/provider changed materially tomorrow, could you identify every affected product/use case, owner, evidence pack and review from one view?`

# ASSET C — TECHNICAL VS OPERATIONAL AI GOVERNANCE

Core thesis:

**Runtime controls and organisational governance records solve different problems. Mature teams connect them.**

## Founder post angle

Hook:

`AI observability is not the same thing as AI governance — and that does not make observability less important.`

Contrast:

Runtime asks:

`Is the system behaving within technical boundaries?`

Operational governance asks:

`Who owns this use case, why is it approved, what evidence supports that decision, and when must it be reviewed again?`

## Company post angle

Title:

**Where runtime governance ends and operational governance begins**

Use matrix:

- traces vs inventory;
- guardrails vs governance rationale;
- evaluation history vs organisational review history;
- technical owner vs accountable business owner;
- runtime incident vs governance review trigger.

## Carousel — 7 slides

1. `Runtime control != organisational governance record`
2. `Technical layer: traces / evals / guardrails / deployments`
3. `Operational layer: use case / owner / rationale / evidence / review`
4. `Both can be strong independently.`
5. `The failure often happens at the handoff.`
6. `Technical change -> governance review trigger`
7. `Mature governance connects the two layers.`

## Newsletter angle

`Your runtime governance may be strong. Is the cross-functional handoff?`

## Sales excerpt

`When an enterprise customer needs both runtime evidence and a governance answer, do those views already live in one operating model or is there a manual handoff?`

# ASSET D — ARTICLE 50 EVIDENCE OPERATING MAP

Core thesis:

**Article 50 is not one universal disclosure rule. The operating unit is system/use case + role/context + implementation evidence + review.**

## Founder post angle

Hook:

`Article 50 is now applicable. That still does not mean “label every use of AI”.`

Teach:

Separate:

- direct interaction with natural persons;
- synthetic content marking/detectability;
- deployer duties for defined uses such as deepfakes or emotion-recognition contexts;
- provider/deployer role and factual context.

Operating chain:

`SYSTEM -> USE CASE -> ROLE -> QUESTION -> OWNER -> IMPLEMENTATION -> EVIDENCE -> REVIEW`

## Company post angle

Title:

**Five Article 50 questions to separate before deciding what to implement**

Safe footer:

`This is an operational framework, not legal advice or automatic classification.`

## Carousel — 7 slides

1. `Article 50 is not one transparency rule.`
2. `Question 1: direct human interaction?`
3. `Question 2: synthetic audio/image/video/text?`
4. `Question 3: defined deployer transparency use?`
5. `Question 4: provider/deployer context?`
6. `Question 5: what implementation evidence exists?`
7. `Govern the conclusion over time, not only once.`

## Newsletter angle

`Article 50: from legal question to operating record`

## Sales excerpt

`Can your team map system, use case, organisational role, transparency question, accountable owner, implementation evidence and review trigger for each material AI use case?`

- `Nachweise`;

Prefer:

- `inventaire IA`;
- `responsable`;
- `preuves`;
- `historique de revue`;
- `gouvernance opérationnelle`.

## Spain

Prefer:

- `inventario de IA`;
- `responsable`;
- `evidencia`;
- `revisión`;
- `gobernanza operativa`.

Do not literal-translate regulatory terminology where official market terminology differs.
