# Enterprise Runtime Closeout Campaign

## Purpose

Execute the largest code-addressable wave of remaining enterprise evidence in one protected operator action, while preserving exact-SHA provenance and the canonical scorecard as the only promotion authority.

## Scope

The campaign dispatches five existing protected workflows for the same full current `main` SHA:

1. Auth/RBAC and organization onboarding proof;
2. live Supabase RLS tenant-isolation proof;
3. distributed rate-limit proof;
4. production runtime, headers, no-store, health, readiness and authenticated smoke proof;
5. branch-protection evidence capture.

Together these workflows cover 22 critical controls across security, identity, tenancy, platform and release engineering. Dispatch acceptance is not evidence that those controls passed.

## Prerequisites

- `enterprise-release-approval` GitHub environment exists and requires the intended operator approval.
- Secrets required by each child workflow are configured in its existing protected environment.
- The production deployment for the target SHA is available before the production runtime proof exhausts its bounded retry window.
- The supplied SHA is the full 40-character current `main` SHA.
- Set `apply_rls_migrations=true` only after reviewing the committed validation migrations and the target project.

## Execution

Open **Actions → Enterprise Runtime Closeout Campaign → Run workflow**.

Provide the exact current `main` SHA. Leave RLS migration application disabled unless the validation schema genuinely requires the committed migrations.

The campaign writes a redacted dispatch receipt containing workflow names, target controls, target SHA and dispatch acceptance. It stores no secrets or provider payloads.

## Acceptance

The campaign itself succeeds when all five workflow-dispatch requests are accepted. Enterprise evidence is accepted only after:

- every child workflow completes successfully for the same target SHA;
- each artifact passes its evidence contract;
- the Enterprise Readiness Scorecard imports the exact-SHA artifacts;
- controls are promoted by the canonical scorecard;
- the enterprise release decision remains fail-closed until all required evidence is complete.

## Failure handling

- **SHA mismatch:** rerun with the current full `main` SHA. Never force an old deployment into the campaign.
- **Missing environment approval:** configure or approve `enterprise-release-approval`; do not remove the protection merely to make the workflow green.
- **Missing provider secrets:** configure the specific child workflow environment. Do not add secret values to repository files, logs or artifacts.
- **Production proof does not converge:** verify the canonical deployment SHA, DNS, health/readiness token and deployment propagation.
- **RLS proof fails:** inspect the live validation artifact and migration state; do not promote tenant controls from repository tests alone.
- **Branch protection remains Exception/Open:** capture durable GitHub API or redacted settings evidence. Do not edit the evidence JSON to simulate completion.

## Rollback

Disable or revert the campaign workflow and dispatcher together. This only removes orchestration; it does not roll back product code, provider configuration or evidence generated by child workflows. Any release decision remains No-Go unless the canonical evidence boundary independently reports Go.
